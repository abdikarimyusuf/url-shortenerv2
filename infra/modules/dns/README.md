# DNS, Route 53 & ACM Notes

## 1. DNS Overview

DNS = System that translates domain names into destinations.

### Basic DNS Flow

Root DNS
   ↓
.com / .co.uk TLD DNS
   ↓
Authoritative Route 53 Nameservers
   ↓
Public Hosted Zone: abdikarim.co.uk
   ↓
DNS Record: api.abdikarim.co.uk
   ↓
Application Load Balancer
   ↓
ECS Service
   ↓
Container


## 2. Key DNS Concepts

| Concept          | Definition                                                        |
|------------------|-------------------------------------------------------------------|
| DNS              | System that translates names into destinations                   |
| Route 53         | AWS-managed DNS service                                          |
| Hosted Zone      | Container where DNS records are stored                           |
| Public Hosted    | DNS zone accessible from the internet                            |
| Zone             |                                                                   |
| Private Hosted   | DNS zone used within a VPC                                       |
| Zone             |                                                                   |
| DNS Record       | Actual DNS routing instruction                                    |
| Nameservers      | Servers authoritative for the domain                             |
| Alias Record     | Route 53 record that points to AWS resources                     |
| Registrar        | Where the domain is registered and nameservers are configured    |

### Important Distinction

Hosted Zone
= Where DNS records live

Nameservers
= Servers that answer DNS queries authoritatively

Registrar
= Where the domain is registered and nameservers are configured


## 3. Common DNS Record Types

| Record Type | What It Does                                      | Common Use Case                         |
|-------------|---------------------------------------------------|------------------------------------------|
| A           | Maps a domain to an IPv4 address                  | Pointing a domain to a server            |
| AAAA        | Maps a domain to an IPv6 address                  | Pointing a domain to an IPv6 server      |
| CNAME       | Maps one domain name to another domain name      | ACM validation or domain aliases         |
| MX          | Specifies mail servers for a domain               | Receiving emails                         |
| TXT         | Stores text-based domain information              | SPF, DKIM, and domain verification       |
| NS          | Specifies the authoritative nameservers           | Delegating DNS to Route 53               |
| SOA         | Stores administrative DNS zone information        | DNS zone configuration                   |
| Alias       | Points a domain to an AWS resource                | ALB, CloudFront, or S3                   |

## 5. ACM DNS Validation

When using DNS validation, ACM generates a special CNAME record.

The purpose of this record is to prove that you control the domain.

### Validation Options

Validation options are the DNS instructions automatically generated by ACM to prove domain ownership.

They contain details such as:

| Field | Meaning |
|---|---|
| `resource_record_name` | DNS record name ACM requires |
| `resource_record_type` | DNS record type, usually `CNAME` |
| `resource_record_value` | Value the CNAME must point to |

Example:

```text
Record Name:
_abc123.api.abdikarim.co.uk

Record Type:
CNAME

Record Value:
_xyz456.acm-validations.aws.

## 6. Certificate Domain Name

The certificate domain can be created by combining Terraform variables:

    domain_name = "${var.subdomain_name}.${var.domain_name}"

For example:

    subdomain_name = "api"
    domain_name    = "abdikarim.co.uk"

Result:

    api.abdikarim.co.uk

ACM then generates validation options for this domain.


## 7. ACM Validation Options in Terraform

ACM exposes the validation information through:

    aws_acm_certificate.this.domain_validation_options

If there is one validation option, you can access it with:

    aws_acm_certificate.this.domain_validation_options[0]

You can then access the individual fields:

    .resource_record_name
    .resource_record_type
    .resource_record_value

Example:

    name = aws_acm_certificate.this.domain_validation_options[0].resource_record_name

    type = aws_acm_certificate.this.domain_validation_options[0].resource_record_type

    records = [
      aws_acm_certificate.this.domain_validation_options[0].resource_record_value
    ]


### If There Are Multiple Validation Options

You can loop through them:

    for dvo in aws_acm_certificate.this.domain_validation_options

dvo = Domain Validation Option

The loop processes each validation option individually.


## 8. ACM + Route 53 Full Flow

    1. Create Route 53 Hosted Zone
              ↓
    2. Request ACM Certificate
              ↓
    3. ACM generates validation CNAME
              ↓
    4. Terraform reads ACM validation details
              ↓
    5. Terraform creates CNAME in Route 53
              ↓
    6. ACM checks the CNAME
              ↓
    7. aws_acm_certificate_validation waits
              ↓
    8. Certificate becomes ISSUED
              ↓
    9. Attach certificate to ALB HTTPS listener
              ↓
    10. Create Route 53 A Alias record to ALB
              ↓
    11. User visits HTTPS domain
              ↓
    12. ALB accepts encrypted HTTPS traffic
              ↓
    13. ALB forwards request to ECS


## 9. Terraform Certificate Lifecycle

    lifecycle {
      create_before_destroy = true
    }

### create_before_destroy

Terraform creates the replacement certificate before deleting the old certificate.

This helps reduce the risk of certificate availability issues during replacement.

resource {                     ← OUTER BLOCK

for_each doesn't loop over the lines below it. It tells Terraform how many instances of the OUTER resource block to create.




aws_acm_certificate_validation
resource {                                      ← OUTER RESOURCE BLOCK

    certificate_arn = ...                       ← Which ACM certificate to validate

    validation_record_fqdns = [                 ← Create a LIST of FQDNs
        for record in ... : record.fqdn         ← Get FQDN from EVERY Route 53 record
    ]

}                                               ← Resource ends
What each part means
for record in ...       ← Go through every Route 53 validation record

record                   ← Current Route 53 record

record.fqdn              ← Full DNS name of the current record

[ ... ]                  ← Collect all FQDNs into a list

validation_record_fqdns  ← Pass that list to ACM validation
